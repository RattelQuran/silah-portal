## ترتيب النشر المقترح (كل خطوة بموافقتك)
1. **D-12:** تلصق نص القواعد المنشورة من Firebase Console. أقارنه بالمقترح وأكتب الفروق.
2. **نسخة احتياطية** من البيانات الحالية قبل أي تغيير (زر «تنزيل نسخة احتياطية» بعد الدمج، أو تصدير من Console).
3. **دمج PR #2** (المرحلة 02) في `main`. هذا ينشر الواجهة على GitHub Pages، ولا يغيّر القواعد.
4. **نشر القواعد** بعد مراجعة الفروق: `firebase deploy --only firestore:rules --project silah-portal`، منك أو بموافقتك.
5. **فحص بعد النشر:** دخول كل دور مرة، وتسجيل حضور تجريبي ثم إلغاؤه.
6. **دمج الاتجاه D** (`web4d/signature-preview`) بعد اعتمادك النهائي.
7. **D-15:** تفعيل App Check مع reCAPTCHA v3 (مجاني) لحماية نموذج الموقع.

## الرجوع عند المشكلة
- الواجهة: `git revert` لدمج الفرع، أو إعادة `main` إلى `restore/2026-11-25-pre-web4d`. GitHub Pages يعيد النشر خلال دقائق.
- القواعد: نسخة النص المنشور الحالي (التي ستلصقها في الخطوة 1) هي نقطة الرجوع، وتُنشر من Console مباشرة.
- البيانات: الاستعادة من ملف النسخة الاحتياطية، مع المعاينة، ودون استبدال افتراضيًا.
