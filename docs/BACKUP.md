# BACKUP — النسخ الاحتياطي والاستعادة

## لماذا هكذا؟
خطة Firebase المجانية (Spark) لا تدعم التصدير المجدول (يحتاج خطة Blaze المدفوعة). لذلك أُضيف نسخ يدوي من البوابة نفسها، بلا تكلفة ولا خادم.

## النسخ (المدير فقط)
البوابة › **الصلاحيات والنقل** › **تنزيل نسخة احتياطية**.
- يُنزَّل ملف `silah-backup-YYYY-MM-DD.json` فيه كل المجموعات الثماني عشرة (`format: "silah-backup"`, `version: 1`) مع عدد السجلات في كل مجموعة.
- الملف فيه بيانات أطفال وأولياء أمور ومال، فاحفظه في مكان خاص (مجلد Drive غير مشترك مثلًا).
- التوصية: نسخة أسبوعيًا، وقبل أي نقل أو استعادة.

## الاستعادة أو النقل
البوابة › **الصلاحيات والنقل** › اختر الملف:
1. يُفحص الملف: صيغة صلة (إصدار 1) أو ملف `rattel-export.json`. يُرفض أي ملف آخر، وأي مجموعة غير معروفة، وتُستبعد السجلات التي بلا معرّف صالح.
2. **معاينة** لكل مجموعة: عدد السجلات في الملف، والجديد منها، والموجود مسبقًا.
3. افتراضيًا **تُضاف السجلات الجديدة فقط**، ولا يُستبدل الموجود.
4. لاستبدال الموجود: فعّل «استبدال». **تُنزَّل نسخة احتياطية تلقائيًا أولًا**، ثم يُكتب فوق السجلات.
5. لا يُحذف أي سجل في أي حالة.

## الاختبارات
- `tests/unit.test.mjs`: تحويل الملف إلى عمليات، رفض الملفات التالفة، وخطة الجديد والموجود.
- `tests/e2e.test.mjs`: نسخ ثم استعادة بلا تغيير، وإضافة سجل جديد دون المساس بالموجود، والاستبدال بعد نسخة أمان، ورفض ثلاثة ملفات غير صالحة.
- `tests/emulator.test.mjs`: نسخة كاملة تحت القواعد المقترحة بلا أي رفض للصلاحيات.

كل الاختبارات تستخدم بيانات وهمية. لم تُنسخ بيانات الإنتاج ولم تُستورد.
